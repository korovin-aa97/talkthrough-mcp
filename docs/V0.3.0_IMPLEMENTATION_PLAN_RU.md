## 1. Цель релиза простыми словами

Главная пользовательская ценность v0.3.0: Talkthrough превращает запись
встречи в протокол с точными репликами и сохранёнными именами участников.

Для этого релиз должен:

1. Точнее делить распознанный текст между голосами на границе слов.
2. Дать агенту или человеку безопасно сохранить соответствие `S1 → имя`.

4. Повторно кластеризовать голоса за секунды, если публичный API движка это
   позволяет без хрупких обходов.

6. Закрыть подтверждённые замечания последней оценки 0.2.6.

Это минорный релиз с новым восьмым MCP tool, аддитивной эволюцией данных,
полной агентской батареей и полной релизной церемонией.

## 3. Зафиксированные продуктовые решения — не переспрашивать

1. В одном релизе делаем и word-level split, и `label_speakers`.
2. Порт на MCP SDK 2.x выполняется первым; новые функции пишутся уже поверх
   него.
3. Word timestamps хранятся только у новых диаризованных jobs компактными
   триплетами `[t0_ms, t1_ms, "слово"]`. Они не отдаются наружу целиком.
4. Схема остаётся `talkthrough-manifest/v1`; используются только аддитивные
   поля, загрузчик остаётся толерантным к неизвестным полям.
5. Исходные speaker labels `S1`, `S2` не удаляются и не заменяются именами.
   `speaker_name` отдаётся отдельным полем.
6. `search(speaker=)` принимает и label, и сохранённое имя.
7. Кэш эмбеддингов диаризации из issue #33 входит в план, но только если его
   можно построить на публичном и устойчивом API sherpa-onnx.
8. Semantic search из issue #15 — однодневный spike с решением владельца.
   При сомнительном качестве переносится в 0.4.0 и не задерживает 0.3.0.
9. MCP elicitation переносится в 0.4.0.
10. `num_speakers="auto"` не делаем: движок не обеспечивает такое обещание.
11. В scope входят `media.path` в `list_jobs`, `match_mode="any_word"`,
    улучшенная straddle-нота и ограниченные OCR name candidates.
12. Все F1–F6 из последней оценки 0.2.6 входят в релиз; F6 с pin версии
    Claude-плагина нельзя снова переносить.

## 7. Шаг B — полностью закрыть findings 0.2.6

### F1. dHash путает разные однотонные экраны

Проблема: dHash видит только градиент и считает однотонные красный, синий,
чёрный и белый кадры одинаковыми. Из-за этого `get_frames(at_ms=...)` может
вернуть не тот цвет и нарушить обещание `valid_from_ms/valid_to_ms`.

Исправление:

1. Сохранить dHash как основной сигнал.
2. Вместе с ним вычислять среднюю яркость того же grayscale thumbnail.
3. Считать кадры дублями только если одновременно:
   - Hamming distance не превышает существующий порог 4;
   - разница средней яркости не превышает отдельный именованный порог.
4. Начать с порога яркости 12 и менять его только на основании тестов, оставив
   объяснение в коде.
5. Не увеличивать сетевой след и не добавлять тяжёлую зависимость.

Тесты:

- красный и синий однотонные кадры остаются разными;
- чёрный и белый остаются разными;
- два одинаковых/почти одинаковых JPEG остаются дублями;
- scripted repro из findings даёт `unique_count=2`, а запрос на 3000 ms
  возвращает синий кадр;
- обычные textured fixtures не дают заметного взрыва unique frame count.

### F2. Неверное имя `longest_turn_ms`

Поле сейчас является timestamp начала, а выглядит как duration.

Аддитивное и совместимое решение для 0.3.0:

- добавить `longest_turn_at_ms` — начало самого длинного turn;
- добавить `longest_turn_duration_ms` — настоящая продолжительность;
- сохранить `longest_turn_ms` как deprecated alias значения `at_ms` на один
  минорный цикл, чтобы старый command pack 0.2.6 не сломался;
- новые guidance, prompt и OCR-кандидаты используют только
  `longest_turn_at_ms`;
- в release notes явно описать alias и будущее удаление не раньше 0.4.0.

### F3. Нет объяснения no-op amend после смены embedding model

No-op note должна появляться при любом намеренном amend, завершившемся
`labels_changed=false`, а не только при явном `num_speakers`.

Добавить в diarization block ограниченное поле причины, например
`amend_reason: "num_speakers" | "embedding_model" | "both"`. Оно необходимо,
чтобы одинаковая честная note сохранялась и позже отдавалась из summary и
transcript. Текст ветвится по причине и прямо говорит, что новая модель или
новое k дали те же labels.

### F4. `gc` предупреждает о каталоге, который сам удаляет

Во время `gc` manifest-less directory не должен сначала выглядеть как
неисправленная ошибка. Для каталога старше sweep-порога выводить один итог:
`found partial dir …, swept`; для молодого или залоченного — спокойную note о

warning-поведение.

### F5. TLS hint не охватывает первый static-ffmpeg download

Не оборачивать внутренности стороннего пакета хрупким кодом. В корпоративный

Добавить docs test или устойчивую проверку наличия этой инструкции.

## 8. Шаг C — word-level speaker split

### Данные

1. `word_timestamps=True` включать только когда diarization реально запрошена.
2. Добавить к `Transcript` опциональный `words`, сериализуемый компактными
   триплетами `[t0_ms, t1_ms, raw_text]`.
3. Поле отсутствует, а не равно `null`, у недиаризованных и старых jobs.
4. Полный массив words никогда не отдаётся в MCP payload.
5. Измерить размер на А360 и overhead STT; ожидаемая цена около 300 KB на
   73 минуты и +10–20%, но в отчёте использовать реальные измерения.

### Детерминированный алгоритм

Для каждого валидного word token:

1. Посчитать overlap со всеми diarization turns.
2. Выбрать turn с максимальным overlap.
3. При равном overlap выбрать turn с более ранним `t0_ms`, затем меньший
   числовой `S<n>`.
4. Если overlap равен нулю для всех turns, оставить speaker неизвестным, а не
   угадывать ближайший голос.
5. Сгруппировать соседние words одного исходного Whisper segment и одного
   speaker в новый segment.
6. Время группы — от начала первого до конца последнего слова.
7. Текст строить конкатенацией raw word strings с сохранением пунктуации и
   внутренних пробелов; удалять только внешний whitespace.
8. `seq` пересчитать последовательно.
9. Если у исходного segment нет ни одного валидного word, оставить его целым
   и применить старую maximum-overlap атрибуцию.

Невалидные timestamps нельзя молча превращать в убедительные данные: считать
их, логировать bounded warning и применять segment fallback.

### Совместимость старых jobs

Старые manifests 0.2.x не содержат words.

- Они продолжают читаться и обслуживаться без миграции.
- `label_speakers` на них работает.
- Amend с новым k **не запускает Whisper скрытно** и использует прежнюю
  segment-level атрибуцию.
- В roster/summary для diarized jobs отдавать вычисляемое
  `attribution_precision: "word" | "segment"`.
- Для старого job с `segment` давать короткую note: точный word split требует
  повторного `process_media(..., force=true, diarize=true)`.
- Автоматическая дорогая перетранскрипция старого job запрещена.

### Amend и echo trim

- Новый job сохраняет words один раз; дальнейший re-diarize с другим k
  повторно использует их без Whisper.
- `labels_changed` сравнивается после нового split на нормализованных
  `(t0_ms, t1_ms, text, speaker)`.
- `vocabulary_echo_trimmed` обязан синхронно подрезать words; слова не должны
  дублироваться или возвращать удалённое эхо.

### Тесты и acceptance

Unit: граница внутри слова, между словами, exact tie, overlapping turns,
gap без turn, пустые turns, segment без words, punctuation/whitespace,
invalid timestamps, no duplicated words after echo trim.

Integration: создать `tests/fixtures/meeting-interrupt.m4a` через
`tests/fixtures/make_fixtures.py` на macOS; тем же коммитом обновить
`tests/integration/fixture_facts.py`.

Real data на scratch-копии А360: известная склейка около
3352860–3358300 ms и случай S6/S7 должны разделяться на границе слова без
потери или дублирования текста.

### Стоп-условие

Если word timestamps на реальном русском материале систематически ухудшают
атрибуцию или текст, остановиться с примерами old/new и вариантами. Не шипить

## 9. Шаг D — `label_speakers`, восьмой MCP tool

### Точный входной контракт

```text
label_speakers(
  job_id,
  labels: dict[str, str | null],
  evidence: dict[str, str] | null = null
)
```

Правила:

- ключ label должен существовать в полном roster этого job;
- строка имени после trim: 1–100 Unicode characters;
- `null` или пустая/whitespace-only строка удаляет сохранённое имя;
- evidence после trim: не более 500 characters на label;
- evidence разрешено только для label, присутствующего в `labels` или уже
  имеющего сохранённое имя;
- удаление имени одновременно удаляет его evidence;
- одинаковые имена для разных labels допустимы: в реальной встрече могут
  быть два Александра;
- search по повторяющемуся имени ищет все соответствующие labels и честно
  сообщает неоднозначность;
- неизвестный label, слишком длинное значение и control characters дают
  ValidationError с перечнем допустимых labels;
- пустое итоговое отображение сериализуется как отсутствие полей, не `null`.

### Хранение и конкурентная запись

- Имена хранятся в существующем `diarization.speaker_names`.
- Evidence получает отдельное аддитивное поле
  `diarization.speaker_name_evidence`.
- Tool захватывает существующий per-job lock, заново читает manifest после
  lock, применяет patch и пишет его через temp file + `os.replace`.
- Сделать manifest save атомарным общим helper, если это можно сделать без
  изменения формата; добавить тест на отсутствие частично записанного JSON.
- Tool идемпотентен и получает честную `LOCAL_WRITE_TOOL` annotation.

### Выходы

- В JSON segments, search hits, roster и `speakers_in_range` добавлять
  `speaker_name` рядом с `speaker`/`label`, только когда имя сохранено.
- Evidence не дублировать в каждом segment. Оно может возвращаться в bounded
  результате `label_speakers` и roster.
- `format="text"` и `format="srt"` показывают имя, но сырой JSON label всегда
  остаётся доступным.
- `search(speaker=)` принимает label или case-insensitive имя.
- Неизвестное имя возвращает honesty note с bounded списком известных имён и
  labels.

### OCR `name_candidates`

Сервер не использует LLM/NER и не должен утверждать, что распознал человека.
Для каждого видимого roster entry:

1. Взять не более трёх уникальных кадров, ближайших к
   `longest_turn_at_ms`, в bounded окне вокруг него.
2. Из уже сохранённого OCR выбрать не более трёх коротких строк, содержащих
   буквы; дедуплицировать case-insensitive.
3. Вернуть элементы вида `{text, frame_ms}`, максимум 120 characters каждый.
4. Поле называется `name_candidates`, но guidance прямо говорит: это сырые
   экранные подсказки, они могут быть должностью, UI-текстом или чужим именем.
5. Если OCR выключен, job аудио-only или подходящего текста нет — поле
   отсутствует.
6. Никакое имя не сохраняется автоматически; решение принимает агент/человек
   через `label_speakers`.

Точное окно и фильтр выбрать один раз в implementation PR, зафиксировать
constants и unit tests; не добавлять сетевой NER.

### Церемония нового tool

- Все descriptions и prompts меняются только в `guidance.py`.
- Добавить 10–15 однострочных примеров не длиннее 120 characters.
- Обновить exact count с 7 до 8.
- Обновить canonical skill и example agent, затем запустить
  `uv run python scripts/gen_integrations.py`.
- Generated files не редактировать вручную.
- `meeting-actions` должен сохранять доказанный mapping, чтобы следующая
  сессия сразу работала с именами.
- Добавить unit, integration и real MCP E2E.

Real acceptance: на scratch-копии А360 применить mapping из
`/Users/alexander/talkthrough-qa/data/a360-names.md`; проверить JSON,

## 10. Шаг E — кэш эмбеддингов диаризации, issue #33

Разобрать процесс только через публичный sherpa-onnx API на стадии:
segmentation → embeddings → clustering.

- Сегментные интервалы и embeddings хранить в versioned sidecar внутри job
  directory, не в manifest.
- Cache key включает embedding model, segmentation model и все параметры,
  меняющие embeddings.
- Явный amend k при cache hit выполняет только clustering.
- Cache miss или несовпадение key выполняет полный проход и атомарно пишет
  новый sidecar.
- Не доверять битому/частичному sidecar; безопасно пересоздавать.
- `delete_job`, `gc` и partial cleanup удаляют sidecar вместе с job.
- Никакой runtime network после прогрева.

Тесты: hit, miss, corruption, invalidation по каждой части key, identical
roster при cached/full run с одинаковым k. Измерить А360/CXP и включить
реальные секунды в отчёт и TROUBLESHOOTING.

Стоп-условие: если для разделения стадий нужны private API, копирование native
logic или vendored fork, остановиться. Владелец решает: отдельный устойчивый
fork или перенос #33 в 0.4.0. Перенос по явному решению не блокирует остальные
части 0.3.0.
